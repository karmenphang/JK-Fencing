# Bing Chillin — Digital Craving & Sales Experience

A sales proposal deck for the manager of Bing Chillin Dessert Cafe, Puchong.
Prepared by Karmen Phang, Executive Operations & AI Support.

**Deliverable:** `Bing-Chillin-Digital-Craving-and-Sales-Experience.pptx`
16:9 widescreen, 8 slides, speaker notes on every slide, about 6 minutes to present.

## What is verified and what is concept

Everything on these slides is either a publicly verifiable fact with a citation on
the slide, or clearly labelled as a concept. Nothing was invented.

**Verified, and cited on the slides**

| Fact | Source |
|---|---|
| Address: 1, Jalan Kenari 9, Bandar Puchong Jaya, 47100 Puchong | @bestfoodmalaysia listing (Threads, 2026) |
| Hours: 11am to 11pm Sun to Thu, 11am to 12am Fri and Sat; pork free | @bestfoodmalaysia listing (Threads, 2026) |
| Melbourne origin; Puchong is the Malaysian outlet | bingchillin.com.au / Chiefeater |
| Menu categories: bingsu and waffles | Chiefeater, 2026 |

**Deliberately not included:** no sales figures, no customer counts, no menu prices,
no testimonials, no performance statistics, no claimed uplift. The cafe's current
marketing is never criticised.

**Labelled as concept:** the craving page, the Find Your Bingsu selector and its
results, the seasonal drop campaign, the WhatsApp conversation, and the pilot scope.
Flavour names, dates and quantities are shown as bracketed placeholders for
Bing Chillin to fill in.

## Imagery

All artwork in the deck is original, generated by `art.js` — abstract cinematic
gradient and bokeh panels in the deck palette. No third party photography, no
logos, no stock images. Slide 1 says so on the slide: the live build would use
Bing Chillin's own photography, with their permission.

To swap in real photos later, replace the files in `img/` at the same dimensions
and rerun `node deck.js`.

## Rebuilding

```bash
npm install pptxgenjs sharp
node art.js      # regenerate the artwork into img/
node deck.js     # build the .pptx
```

## QA

LibreOffice's Impress import filter is unavailable in this container, so `qa/`
holds a small purpose built checker instead:

```bash
python3 qa/parse.py <deck>.pptx qa/layout.json   # geometry + text -> JSON
node qa/render.js                                # approximate PNG render per slide
```

The renderer approximates text metrics, so word spacing in its output is tighter
than PowerPoint's. It is reliable for layout, overlap and overflow (boxes whose
text does not fit are outlined in magenta), not for final typography.

`scripts/office/validate.py` from the pptx skill passes clean on the deck.
